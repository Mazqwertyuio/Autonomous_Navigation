# Чистий NoMaD: базовий експеримент

Поточний типовий режим основного CLI — `pure-nomad`. Він запускає наявні ваги
NoMaD з `goal=None`, тобто `goal_mask=1`, без фотографії-цілі.

## Запуск

Перевірка на записі:

```powershell
.\venv\Scripts\python.exe tello_nomad_autopilot.py --pure-nomad --device cpu --video flight_live_last.mp4 --max-frames 120
```

Політ після підключення комп'ютера до Wi-Fi Tello:

```powershell
.\venv\Scripts\python.exe tello_nomad_autopilot.py --live --pure-nomad --device cpu
```

У відеовікні: `T` — зліт, `N` — увімкнення/вимкнення автопілота,
пробіл — вимкнення автопілота та зависання, `L`/`Q` — посадка, `R` — очищення
контексту. Фотоцілі, підцілі та розмітка зон у цьому режимі вимкнені.
Після зльоту й перемикання автопілота контекст починається заново.

## Що саме працює

```text
RGB → контекст кадрів → NoMaD(goal_mask=1) → одна траєкторія
    → Pure Pursuit → лінійне перетворення (v,w) у Tello RC
```

Мережа повертає waypoint, а не готові команди Tello, тому Pure Pursuit та
перетворення одиниць залишаються частиною базового запуску.

- Немає DroNet, DA2, евристик стін/вікон, заборонених зон, VLFly або novelty.
- Немає сортування траєкторій, EMA, deadband-підсилення, сповільнення на
  поворотах, бокового руху, автоматичного заднього ходу чи recovery.
- Зовнішній регулятор ToF вимкнений, `UD=0`. Працює власна стабілізація Tello;
  ToF та IMU лише записуються до журналу.
- Ручні зупинка й посадка залишаються доступними. Зовнішнього захисту від
  зіткнень у базовому режимі немає.

Типові параметри: DDIM, 4 ітерації, 1 семпл, seed=0. Це поточний NoMaD-адаптер
з прискореним семплером, не повний 100-кроковий DDPM. Кількість ітерацій можна
задати через `--diffusion-iters 2`, `4`, `10` тощо; більша кількість збільшує
затримку. Pure-режим вимагає одного семпла, щоб виключити зовнішній вибір гілки.
Ваги моделі не змінювалися і не донавчалися.

Збережено чинні обмеження команд: `v_max=0.35`, `w_max=0.45`, `lookahead=0.25`.
Pure Pursuit використовує всю траєкторію. RC-мапінг: лінійні межі FB ±22,
yaw ±28, LR=UD=0. Ці коефіцієнти не є калібруванням фактичної швидкості Tello.

## Дані експерименту

Кожна live-сесія створює:

- `flights/flight_*.mp4` — відео з HUD;
- `flights/flight_raw_*.mp4` — сирий потік без накладеної траєкторії;
- `flights/telemetry_*.csv` — стан, команди, `control_profile`, параметри дифузії,
  тривалість кроку. У pure-режимі hazard=`DISABLED`, recovery=`NORMAL`;
- `flights/config_*.json` — повна конфігурація, seed, пристрій, версія PyTorch,
  семплер та назви відеофайлів.

Копії останнього запису: `flight_live_last.mp4`, `flight_raw_last.mp4`,
`telemetry_live_last.csv`. Для подальшого інференсу краще використовувати
`flight_raw_last.mp4`, щоб старий HUD не потрапляв до моделі.

MP4 зберігається з 20 FPS, по кадру на рядок CSV. Реальний темп польоту треба
відновлювати за CSV timestamps. Офлайн-прогін перевіряє обчислення та реакції на
кадри; він не відтворює політ після зміни команд і не доводить уникнення зіткнень.

Комбінації `--pure-nomad` зі щитами, VLFly, novelty або іншою моделлю
відхиляються. Старі комбіновані режими залишені для подальших окремих порівнянь.
